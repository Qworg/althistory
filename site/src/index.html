From the record to the road not taken

Bring in history

Paste text, or give it a Wikipedia article or a Wikidata ID. The events it finds come back in a review table, where you edit, drop or keep each one. Nothing is written until you approve.

Pattern extraction runs offline. Add an Anthropic or OpenAI key to have a model read the prose as well.

See it in time

Events sit under the periods that contain them, nested as deep as the history needs. Select one to trace what it caused: its effects stay lit on the timeline while the rest fades back.

Or follow one actor through it all: what a person, state or institution did, and what was done to them. Clusters of events are read for the economic, social and political pressures behind them.

Follow the causes

Every link between two events is direct, indirect or contributory, and carries a weight, a confidence and the evidence for it. Lay the graph out the way that reads best, and find every path from one event to another.

Change one thing

Branch a history at any moment and write what happens instead. The original stays drawn faintly beneath, so you see where the two part. Compare branches side by side, and merge one back through a conflict resolver that flags what doesn't fit. Every graph is versioned, so any change can be rolled back.

Everything the app does, from a script or an agent

The althistory CLI answers in JSON on stdout, with exit codes that say what went wrong. althistory schema describes every command, so an agent can learn the tool by reading it.

Run althistory mcp and Claude, Cursor or any MCP client gets the same tools. Give it a premise and it drafts a history for you to edit.

Run npm link once in the repository to put althistory on your PATH; the MCP config assumes it. For generated histories, set ANTHROPIC_API_KEY or OPENAI_API_KEY; without one you get a template to fill in.

Run it on your machine

You need Node 20 or later, and nothing else: local mode keeps every graph in JSON files, so there's no database to set up. Then open localhost:5173.

Your own install adds what the demo can't: bringing in history, exporting, merging and simulating. For a shared server with Neo4j and Redis, see production deployment.
