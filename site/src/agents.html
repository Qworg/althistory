Build histories with an agent, real or invented

Every screen of the app is also a CLI command that answers in JSON, and althistory mcp gives Claude, Cursor or any MCP client the same tools. Bring a premise from real history, or a world nobody has written yet. The agent does the writing, and althistory checks that the dates and causes hold together.

Install it

You need Node 20 or later. npm link puts althistory on your PATH, which the MCP configs below assume; without it, use the full path to bin/althistory in the repository.

Local mode keeps every graph in JSON files, so there is no database to set up. althistory status reports the mode it is running in.

Connect an agent over MCP

althistory mcp is a stdio MCP server. Add it to Claude Desktop, Cursor or Claude Code, and the agent can create graphs, write events, ages and causal links, check them, and branch them for you. If the app is running, the server works through it, so what the agent writes appears as it goes; otherwise it works on the files directly.

The server also offers three prompts, one for each way of working described below. In Claude Code they appear as /althistory:worldbuild and so on: run one on its own, then describe your world or premise in your next message.

No extra API key needed. Claude writes the history itself through the tools. Only the drafting tools, generate_timeline and branch_timeline, call a model of their own, and only if the server has ANTHROPIC_API_KEY or OPENAI_API_KEY in its environment (env in the config, or -e on the command). Without one they return a generic skeleton marked "source": "template" for the agent to rewrite. They also need the app stopped.

You never start althistory mcp yourself: your client runs it, and talks to it over stdin and stdout. If your client cannot find althistory, give the full path to bin/althistory in the clone; it needs node on the client’s PATH.

Three ways to work

Each is a prompt the server offers. Pick it in your client, or just ask in your own words: the prompt only gives the agent a plan to follow.

Bend real history

Start from a premise and the moment real history turns. The agent drafts what follows and corrects the years before the turn from what it knows really happened; althistory checks that every consequence comes after its causes.

“Draft a history where Byzantium wins at Manzikert, then show me where it’s weakest.”

Prompt
alternate_history
Tools
generate_timeline, ingest_text, link_events, branch_timeline

Invent a world

No real history underneath: the agent writes the world’s ages, events and causes, and althistory keeps them consistent. The graph keeps the world’s own calendars, of any shape, so the app, the tools and the exports write “Thaw 4, 312 AR” in a year of twelve months and two festivals, and a day of thirty hours.

“Help me build the history of Vael, a drowned archipelago where salt is money.”

Prompt
worldbuild
Tools
create_graph, create_arc, create_event, link_events, validate_graph

Grow what you have

Hand the agent a graph you already have. It reads the whole history, writes one open thread forward, and branches wherever you can’t choose. A simulation can suggest what comes next, but it is a rough model of pressures between actors, not prose.

“Read my Vael graph and write the next fifty years of the Glass Republic.”

Prompt
grow_history
Tools
export_context, simulate_timeline, validate_graph, branch_timeline

The tool names drop their althistory_ prefix here. Without MCP, althistory prompt worldbuild world="…" --plain prints the same brief for any agent that can run a command.

Inventing a world, start to finish

An abridged session with the worldbuild prompt. The agent settles the calendars first, lays out three ages, writes the events and links their causes.

Then one link is refused: the agent claimed the glassmakers started the Tide War, but they only joined it eleven years in. Instead of forcing the link, the agent writes the grievance that actually turned them.

Every date is one moment on the graph’s timeline, and the world’s calendars name it. Vael’s Reckoning has twelve months of thirty days, Midyear’s Day and the four Drowned Days, in a day of thirty Earth hours divided into twenty of its own; the coast keeps the Tide-count beside it. The tools take dates as the world writes them (“Midyear’s Day, 141 AR”, or “Thaw 312 AR” for a month) and give them back the same way beside each date’s place on the timeline, as the Markdown export does.

See your world

The agent’s graphs are files in timeline/data in your clone, the same store the app reads. Start the app with ./start-local.sh, open localhost:5173, and pick the graph: its timeline, causal graph and dates read in the world’s calendars, and the header switches between them.

Use the CLI

Every command prints JSON on stdout and its progress on stderr, so its output can go straight into a script or an agent. althistory schema prints the JSON Schema of every command, with the required options marked, so an agent can learn the tool by reading it.

Generating a history from a premise, or a world from a description, uses a model when ANTHROPIC_API_KEY or OPENAI_API_KEY is set; without one you get a template to fill in. Drafting runs in process, so stop the app first; every other command works with it running. Ingestion reads text with patterns offline and adds a model when it has a key.
