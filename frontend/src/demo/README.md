# The in-browser demo

`npm run build:demo` builds the real frontend for GitHub Pages
(<https://qworg.github.io/althistory/demo/>), with no backend: every API call is
answered in the browser. A normal `npm run build` contains none of this code.
`DEMO_MODE` is a constant Vite inlines, so the demo branches are dropped.

| File | What it does |
| --- | --- |
| `flag.ts` | `DEMO_MODE`, from `VITE_DEMO_MODE` (set in `frontend/.env.demo`). |
| `install.ts` | Imported first by `main.tsx`; points `axios.defaults.adapter` at the server before `services/api.ts` creates its instance. Also reads `?start=branch` (the landing page's link) so a fresh visit opens on the example branch. |
| `server.ts` | The adapter. A live store of events, arcs and causal links (kept in `sessionStorage`, so edits last for the tab); in-memory branching (a branch copies its parent's live store under a new graph id, and the graph routes answer for it); the recorded answers for every other read; then a 405 saying the feature needs the server. |
| `recording.json` | What the real backend answered, generated by `npm run demo:record` in `media/`. |
| `DemoBanner.tsx` | The strip above the app: what to try first, **Start over** (a fresh visit, on the branch), and a link to the repository. |

Two other things change in the demo build: `App.tsx` uses hash URLs, because
Pages serves files and cannot answer `/causal-graph` with the app, and
`main.tsx` doesn't register the service worker.

## Regenerating the recording

```bash
cd media && npm run demo:record      # add -- --skip-build to reuse the last build
```

It runs the same private stack and seed as the screenshots: it walks the app
through every screen for both graphs and keeps every answer. Re-record when the
seed changes or a view starts asking for something new. A request the demo has
no answer for shows up as a 405 "needs the server" error in the app. The
recorder names IDs after the seed's keys, so a re-recording only changes what
changed.

## Testing

- `src/demo/server.test.ts`: the adapter, in Vitest.
- `e2e/demo/demo.spec.ts`: the built demo in a real browser, checking that nothing leaves the page (`npx playwright test -c playwright.demo.config.ts` in `e2e/`). The Pages workflow runs it before it publishes.
